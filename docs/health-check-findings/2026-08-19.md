## Root cause (finding #1, the new one)

`fetch_remote_head` always returns `checked_at`, but `probe_project`'s early return for local-only projects (`repository` empty/unparseable, e.g. `Adobe-Stock-Upload-Assistant`) returned a dict without `checked_at` or `default_branch`. `refresh_project` then accessed `probe["checked_at"]` on every non-fresh path (success, evidence-unavailable, schema-invalid), raising `KeyError`, which the generic exception handler turned into `refresh_failed` with rollback — so the failure was permanent and indistinguishable from a real refresh failure.
